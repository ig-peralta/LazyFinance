# Stage C — expanded experience

Stage C broadens the experience based on the outcomes and remaining needs of
[Stage B](../stage-b/README.md). The [product vision](../../product/product-vision.md#stage-c--broaden-the-experience)
identifies possible directions: voice after reliable text interaction, advanced
analysis, additional providers and other validated financial capabilities.

## Direction is not a selected backlog

The [Linear snapshot](../snapshots/backlog-2026-11-02.md#sprint-c-stage-c--expanded-experience-not-yet-planned-at-issue-level)
contains no Stage C issues. It is historical planning evidence, not a live count.
The planning rule is to select and create Stage C issues **after** the Stage B gate
and review; this folder does not invent issue IDs, owners, priorities or dates.

Voice, projections, anomaly detection and further adapters are candidates, not
automatic release commitments. Shared/family/organization ownership and future
action-oriented features would require their own product and permission rules;
they must not be inferred from the infrastructure or authentication changes.

## Planning and completion

- Use the [shared record template](../stage-sprint-record-template.md) to record
  the agreed goal, selected issues, dependencies and acceptance evidence.
- Apply the [Stage C Definition of Done](definition-of-done.md) to the selected
  work, then use the separate [product release checklist](../product-definition-of-done.md).
- Preserve any resulting closure record and retrospective in this folder rather
  than presenting candidate scope as a completed sprint.
