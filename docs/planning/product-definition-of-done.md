# LazyFinance — Product Definition of Done

This is the **exit checklist for a usable LazyFinance product release**, not a claim that the product is already complete. The [product requirements](../product/product-requirements.md) describe agreed behavior; the [planning snapshot](snapshots/backlog-2026-11-10-stage-c-planning.md) records issue-level scope, and the [stage definitions of done](README.md#stage-gates) cover staged delivery. Stage B's [GO to Stage C planning](stage-b/closure.md) accepts development-stage limitations; it does not check off this release checklist.

LazyFinance is Done for its agreed release scope only when the team can demonstrate and verify **all** of the following:

- [ ] **Release scope is explicit.** The product requirements identify the capabilities committed for this release, their acceptance criteria, and any intentionally deferred capabilities. Every committed issue is delivered or explicitly re-scoped with an explanation; a Todo issue is not described as shipped.
- [ ] **A trustworthy personal-finance flow works end to end.** With representative CLP data, an authenticated user can interpret checking, savings and credit-card balances; inspect movements without treating internal transfers as spending or income; compare comparable periods; trace spending against budgets; distinguish savings targets from measured contributions; and separate planned from confirmed received income. The dashboard and backend agree on amounts, periods, ownership, and the meaning of incomplete or stale data.
- [ ] **The first-party assistant is useful and grounded.** LazyFinance's **own text agent** answers representative Spanish questions using shared user-scoped financial capabilities. Answers identify source amounts, periods, assumptions, estimates and unsupported requests; evaluate the selected live model rather than relying only on scripted fixtures. Models may prepare bounded proposals/read status, never approve or execute. Explicit saved-version approval, ownership/freshness/expiry checks and atomic durable receipts protect the delivered actions. No money movement or invented savings progress is presented.
- [ ] **Connected banking and external access work within the agreed scope.** The neutral connector/Fintoc adapter links supported accounts, imports and refreshes without duplicates, preserves decisions and reports freshness/failures under the current tracking policy. Authorized MCP clients use owned reads and only separately consented bounded writes, with stable request IDs and current preview fingerprints where required. Validate supported client combinations and explicitly identify unavailable capabilities; broader MCP management is not implied by the existing executor.
- [ ] **Identity and data boundaries hold.** Firebase-backed sessions and authorized HTTP, MCP, agent, and provider flows reject invalid or expired access. Two distinct users cannot read or change each other's accounts, transactions, tags, budgets, income declarations, connections, or conversations. Demo authentication is isolated from real-user operation.
- [ ] **The release is repeatable and verified.** A clean setup can apply checked-in migrations, start the services, load representative demo data, and reproduce a complete demonstration. Automated and targeted manual checks cover the agreed behaviors, important edge cases, user isolation, error paths, and relevant non-functional expectations; results, limitations, and fixes are recorded. Production builds and type checks pass for the release baseline.
- [ ] **The delivered product is operable and explainable.** Current setup/configuration, deployment, architecture and data meanings, API/MCP and agent contracts, supported flows, and known limitations match the actual release. A new developer can run and verify it using the documented steps. A final product review demonstrates the committed flows on a known build and records open risks or approved deferrals before release.

Stage C now [selects live voice and everyday-experience improvements](stage-c/planning.md),
including automatic selected-account banking, the persistent assistant and
accessible personalization. These must meet their own issue/stage checks before
being described as delivered. Quotes, a synthetic banking-action demo, alerts and
WhatsApp remain optional unless explicitly promoted. Broader MCP management,
advanced forecasts/anomalies, additional bank adapters, historical backfill and
shared ownership are not selected; real money movement is not authorized. Stage
selection does not replace the release review or waive its unresolved risks.
